# M5 首页数据变动信息流结果

日期：2026-07-30
对齐基线：Android `v1.7.0@419313d`

## 结果

首页已接入成绩、课程表、考试安排和作业四类同步前后差异。每次对应业务刷新成功后，应用先比较当前账号的旧快照与新快照，再替换页面数据；检测到的新增、修改和删除会进入账号隔离、可持久化、可清除的数据变动信息流。

本切片没有改变冻结的 Android 根工程。实现位于 `multiplatform/`，临时视觉预览入口已删除，正式 iOS 与 macOS 产物均重新显示真实登录页。

## 差异算法

共享 `detectDataChanges` 接收稳定身份、内容等价规则和新旧列表，输出 `ADDED`、`MODIFIED`、`DELETED`：

- 同一稳定身份出现多次时按出现次序配对，不会因 `associateBy` 覆盖而丢失重复项。
- 先按新列表顺序输出新增/修改，再按旧列表顺序输出删除，结果可预测。
- 数据库自增 ID 不参与业务身份或等价判断，避免重写缓存后产生伪变动。
- 变动记录器是附属链路；记录失败不会让已经成功的业务刷新显示为失败，协程取消仍正常向上传播。

四类稳定身份按 v1.7.0 行为和现有数据边界定义：

| 数据域 | 稳定身份 | 不参与身份的字段 |
| --- | --- | --- |
| 成绩 | 课程名、教师、学年、学期 | 数据库 ID |
| 课程表 | 课程 ID、是否当前学期、上课时间、地点索引 | 数据库 ID |
| 考试 | 考试类型、课程名 | 数据库 ID |
| 作业 | 课程名、平台作业 ID (`upId`) | 数据库 ID、内部序号 |

## 信息流与持久化

`CacheStoreHomeChangeFeedRepository` 使用当前 `accountScope` 读写 SQLDelight 元数据，保存已建立基线的数据域和未读变动：

- 首次同步且本地没有旧快照时只建立基线，不把服务器全量数据误报为“全部新增”。已有缓存时，第一次刷新仍会报告相对缓存的真实差异。
- 相同变动按稳定键去重，新变动追加到现有未读记录，最多保留 100 条。
- 支持按数据域标记已读和全部标记已读；清除未读记录不会删除已建立的同步基线。
- 退出账号继续沿用既有账号缓存清理路径，不会读取或覆盖其他账号的信息流。
- 编解码采用带版本的长度前缀格式，覆盖中文、分隔符和损坏输入；变动摘要不保存作业正文、附件内容、Cookie、验证码或凭据。

成绩、课程表、考试和作业四个 `ScreenModel` 均在远端刷新成功、替换缓存前调用各自记录器。首页直接订阅该账号的信息流，显示总数和各域新增/修改/删除计数；点击数据域可查看旧值与新值、按域标记已读，或跳转到对应真实业务页面。

## 视觉与交互验证

使用临时的非敏感虚构快照检查了两种正式布局，随后删除预览代码并重建：

- iPhone 17 Pro / iOS 26.5：紧凑首页能完整显示四类计数；成绩详情弹层显示修改前后与新增记录；“标记已读”后总数由 5 变为 3，成绩行消失。
- macOS 27.0：宽窗口四类摘要无截断；成绩详情弹窗的“标记已读”“关闭”“前往页面”均可访问，旧值与新值层级清楚。
- 正式 iOS 与 macOS 产物重新安装/启动后均回到登录页；源码扫描 `TEMP_HOME_CHANGE` 和 `HomeChangeFeedVisualPreview` 为零命中。

以上证明共享状态和 UI 交互，不代表学校服务器真实数据已经产生过可观察变动。2026-08-01 iOS 有效会话已完成一次真实首页刷新：缓存计数为成绩 26、课程 43、考试 9、作业 4，信息流保存 1 个账号基线，`PRAGMA quick_check=ok`；本次没有服务器数据变化，因此只证明刷新、缓存和空变化基线，四类真实新增/修改/删除仍待自然或可控样本。
