# M5 课程表纵向切片实施计划

> 基线：官方 `v1.7.0@419313d` 隔离源码与 Android 脱敏实机记录  
> 修改范围：仅 `multiplatform/` 与迁移文档；冻结 Android 根工程保持只读  
> 状态：App 内课表实现、构建与真实 iOS 课表数据验收完成；小组件按用户决定延后到公版主应用完成后

## 基线结论

- 教务系统有两张课表：`stuschedule/` 为“本学期课表”，`courseselecttask/schedule/` 为“选课课表”。旧代码字段 `isCurrentSemester=true` 实际对应后者，迁移层必须用显式类型隔离这个历史命名反转。
- 每张表按 7 个节次 × 7 天解析；缓存位置沿用 `slot * 8 + day`，有效值为 1–7、9–15、…、49–55。
- 周次 0 表示“全部”。v1.7.0 源码实际提供 1–26 周；脱敏截图中只同时看到了前 14 项，不能把“可见 14 项”误写成“总共 14 周”。
- 本学期课表首次进入时跟随当前周；选课课表默认显示全部。当前周优先使用已缓存值，旧 App 再从教室页面重定向 URL 的 `zc` 参数补充。
- 课程详情包含课程名、编号、教师、周次、地点和节次；同一网格位置允许多门课程。

## 数据与状态

1. `CourseScheduleHtmlParser.kt`：解析教师映射和两类 7×7 课表，不在错误中保留响应正文。
2. `CourseScheduleRemoteDataSource.kt`：复用登录 Cookie，会话内顺序获取教师映射、本学期、选课课表和 HTTPS 当前周提示；四步全部成功后才返回快照。
3. `CourseScheduleRepository.kt`：缓存优先、账号隔离、课程与当前周同事务替换；网络或解析失败保持旧快照。
4. `CourseScheduleScreenModel.kt`：管理课表类型、当前周、用户周选择、星期选择、详情和同步状态；切换到本学期时跟随当前周，切换到选课课表时回到全部周。

## Apple 布局

- iPhone/紧凑窗口：顶部用两个可读的课表类型选项；周选择使用底部 sheet；星期一至星期日使用可换行选择控件；主体按节次纵向排列，只显示所选星期，避免必须横向滚动的八列小字。
- iPad/中等窗口：优先使用与 macOS 相同的周网格；若窗口不足则退回星期纵向列表。
- macOS/宽窗口：侧栏统一切换“成绩 / 课程表”；主区显示完整周网格，右侧常驻课程详情；刷新时保留已有网格。
- 动效只使用系统 sheet 和状态切换；普通课表刷新不弹跳、不清空旧内容。

## 验证

- 解析：两类 HTML、教师回退、空单元格、多课程、坏表格、位置映射。
- 远端：请求顺序、会话过期、任一步失败不产生部分快照、当前周 URL 解析。
- Repository：缓存优先、原子替换失败保留旧缓存、账号隔离、重开恢复。
- 状态：首次跟随当前周、手动选周后不被覆盖、切换课表、星期和详情。
- UI：iPhone 无横向滚动、macOS 七日网格/详情、加载/缓存/空/错误状态。
- 构建：Desktop 测试、Android debug/release、iOS 两架构、Xcode Simulator、macOS distributable、冻结摘要和凭据扫描。

## 当前周安全边界

不迁移旧 App 的明文 IP `http://123.121.147.7:88/...`。本切片只使用已登录教务系统的 HTTPS `classroom/timeholdresult/room_view/` 重定向 URL 中 `zc` 参数；缺失或超出 1–26 时安全回退为 0（全部周）。这属于 `goal.md` 已明确要求的安全修正，不改变课表筛选语义。
