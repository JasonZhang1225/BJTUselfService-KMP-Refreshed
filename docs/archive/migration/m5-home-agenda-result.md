# M5 首页周议程与 DDL 结果

> 基线：官方 `v1.7.0@419313d` 隔离源码与 Android 真实页面盘点  
> 范围：本周七日议程、作业开始/截止、考试日期、48 小时作业提醒、首页刷新协调  
> 结论：共享规则、iPhone/macOS 自适应 UI、三端构建和脱敏视觉验证通过；真实账号数据待 CAS 风控解除

## 1. 基线口径

官方 v1.7.0 首页实际使用 Monday-to-Sunday `WeekCalendar`，不是整月日历：

- 当前周从周一开始，标题显示当前教学周。
- 作业 `openDate` 标记为“开始”。
- 作业 `endTime` 先减 1 分钟再归属日期，因此 `00:00` 截止归到前一天，与 Android 基线一致。
- 考试日期取 `examTimeAndPlace` 的首个 `yyyy-MM-dd` 字段。
- 未提交且距截止还有 `0..48` 个完整小时的作业进入紧急提醒。

KMP 没有继续引入 Android 专用日历库，而是把这些规则写成纯 Kotlin `HomeAgenda`，再由共享 Compose 渲染。

## 2. 共享实现

`buildHomeAgenda()` 显式接收 `today`、`now` 和 `TimeZone`，不在领域规则中偷偷读取系统时钟。返回：

- 固定七天的 `HomeAgendaDay`。
- 每天的开始作业、截止作业和考试列表。
- 按截止时间排序的 48 小时 DDL 列表。

无法解析的作业或考试日期只跳过对应日历标记，不让一条异常学校数据破坏整个首页。DDL 继续复用已测试的 `isHomeworkDueSoon()`，已提交作业不会进入提醒。

## 3. 首页状态与刷新

登录后的应用壳会在首页首次显示时同时初始化：

- 首页 MIS 三状态。
- 作业缓存/网络状态。
- 考试缓存/网络状态。
- 课程表当前教学周。

首页刷新改为并行调用以上四个既有 ScreenModel；只刷新首页会显示的数据，不建立重复 Repository 或旁路网络请求。各模型原有的缓存回退、会话失败和并发保护保持不变。

点击 DDL 或作业事件进入真实“作业”切片；点击考试事件进入真实“考试安排”切片。iPhone 顶部刷新和 macOS 首页按钮都调用同一协调路径。

## 4. 自适应界面

### iPhone

- DDL 卡优先显示提醒、最多三条摘要和全宽“查看作业”。
- 七个日期按钮在一行内显示星期、日期和事件数，当前选择与今天使用不同语义色。
- 选择日期后在下方显示当天事件；“开始/截止/考试”标签直接说明事件类型。
- 视觉样本中七个日期按钮、两条 DDL、日期标题和事件详情均无截断或横向滚动。

### macOS

- 七日控件使用可调整宽度的横向布局，事件详情常驻在周卡下方。
- 首轮视觉检查发现 DDL 操作被拉成手机式整行按钮；已改为宽屏左侧摘要、右侧“查看作业”，紧凑窗口仍保留全宽按钮。
- 没有加入自动翻页或弹跳动画；日期点击立即改变选择和详情，符合可预测、可中断的状态反馈。

## 5. 测试与构建

新增 4 项领域测试：

1. 任意当前日期都生成周一至周日七天。
2. 作业开始日期与午夜截止减一分钟口径。
3. 考试日期解析与畸形数据拒绝。
4. DDL 排除已提交作业并按截止时间排序。

全量结果：

- Desktop：200 项测试，0 失败，0 错误，0 跳过。
- Android debug APK：通过。
- iOS Simulator arm64 framework：通过。
- macOS distributable：通过；严格签名校验成功，主程序为 arm64。
- Xcode iPhone 17 Pro / iOS 26.5 Simulator host build：通过；只有既有 ICU deployment warning。
