# M6 macOS 菜单与快捷键结果

> 范围：macOS 原生菜单栏、共享页面导航命令、刷新当前页面快捷键  
> 结论：实现、自动化测试、三端回归与 Computer Use 菜单状态检查通过；登录后真实页面切换仍随 CAS 风控解除后的逐页验收补证

## 1. 用户可见能力

macOS 应用现在提供两个菜单：

- “前往”：首页、成绩、课程表、考试安排、作业、课件、其他功能、教室、邮箱和设置。
- “数据”：刷新当前页面。

快捷键遵循 macOS 常见约定：

- `⌘,`：进入设置。
- `⌘R`：刷新当前页面。

菜单不是单独维护的假导航。平台侧发送一次性 `AppCommand`，登录后的共享应用壳根据当前 `AppSection` 切换真实页面或调用对应 ScreenModel 的刷新链路。

## 2. 登录生命周期

`AppCommandBus` 使用无重放的 `MutableSharedFlow`：

- 只有当前已挂载的认证应用壳能接收命令。
- 登录页期间发送的命令不会排队，也不会在未来登录后突然执行。
- `subscriptionCount` 驱动菜单可用状态；未登录时所有页面与刷新菜单项均禁用。
- 命令不写入数据库、普通设置或安全存储，关闭应用后没有残留状态。

这一区分了“关闭/未登录时没有命令目标”和“登录后有真实页面目标”，避免菜单看似可用但没有结果。

## 3. 验证结果

新增两项共享测试：

1. 活跃应用壳只收到一次菜单命令。
2. 未登录时发送的旧命令不会在订阅建立后重放。

全量门禁：

- Desktop：193 项测试，0 失败，0 错误，0 跳过。
- Android debug APK：构建通过。
- iOS Simulator arm64 framework：构建通过。
- macOS distributable：构建通过，主程序为 arm64，严格签名校验通过，bundle id 为 `team.bjtuss.bjtuselfservice.desktop`。
- Xcode iPhone 17 Pro / iOS 26.5 Simulator host build：通过；仅有既有 ICU deployment warning。

Computer Use 在最新正式 macOS 构建的登录页实际展开“前往”菜单，确认十个条目均由系统标记为 `(disabled)`；菜单栏同时正确显示“设置… `⌘,`”和“刷新当前页面 `⌘R`”。这证明未登录生命周期与实现一致。

CAS 风控解除后需要再补登录态证据：菜单切换到至少两个真实页面、`⌘,` 进入设置、`⌘R` 只刷新当前页面且不会并发重复触发。

## 4. 保留边界

- macOS 校园网续费按用户最新决定直接交给默认浏览器，不经过分享面板或剪贴板；该行为与菜单能力相互独立。
- 本切片不实现后台自动同步、通知或 Dock 菜单；这些需要有真实同步事件和用户偏好链路后再接入。
- iOS 不照搬桌面菜单结构；iPad 键盘命令若后续增加，应使用 UIKit/SwiftUI 平台入口并复用同一命令语义。
