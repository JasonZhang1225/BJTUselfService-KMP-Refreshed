# macOS 课程回放：下载与播放后续完善

**状态：2026-10-31 起生效。** 适用分支 `feat/courseware-fallback-playback`。

产品范围已调整：**录像下载与合成仅 Windows / macOS**；Android / iOS 只保留在线播放（入口由 `playbackRecordingDownloadAvailable` 关闭）。课件文件下载不受影响。

本文模仿 [Windows 完成基线](playback-four-platform-acceptance.md#4-windows-完成基线) 的验收深度，以及 [Android 计划](playback-android-performance.md) 的「先测后改、一项一提交」节奏，专门安排 **macOS 下载 + 播放** 的后续任务。统一审查条目仍用 F01–F14（见四平台标准）；Windows 的数值与 GPU 路径不得照搬为 Mac 通过条件。

## 2. 当前 macOS 能力快照（源码级，≠已验收）

| 能力 | 现状 | 相对 Windows 缺口 |
| --- | --- | --- |
| 在线播放 | 系统浏览器打开本地 HTML 播放页 | 需真机：暂停/拖动/调速/双路同步/全屏/返回（F03） |
| 预览 | AVFoundation 截帧 helper（随包） | 需核对失败/重试/取消；缺 helper 时的占位（F02） |
| 单路下载 | HLS → TS→MP4 无损转封装 + 流式保存 | 需整节真实下载与体积/路径验收（F04/F06/F10） |
| 双路合成 | `MacHelperVideoCompositor`（helper） | 需整节左右布局、音轨策略、完整解码；压缩音频路径须测样本哈希，不能只凭 `outputSettings=nil`（F05/F06） |
| 队列 | 共享 `PlaybackTaskManager` | 三任务排队/取消/失败推进须本机复验（F07） |
| 中断恢复 | 桌面持久化弱于 Windows 已验深度 | 先列明进程退出后能做什么，再设计恢复；未实现前 F08/F13 标待补齐 |
| 保存入口 | 共享路径字段；**打开文件/文件夹按钮目前主要接 Windows** | 补 NSWorkspace 打开/定位、中文/空格路径、失效提示（F10） |
| 生命周期 | 单窗口；关窗≠退出（托盘设置） | 关窗/Dock 重开/菜单退出/强退分别测；禁止多源码实例、不碰安装版（F12） |
| 安装包 | DMG + helper | 验收包与 helper 哈希、构建标识一致（F14） |

## 3. 阶段划分（对标 Android P0 → P1）

### 3.1 P0：真实整节与能力差距验收（先测，不改生产路径）

目标：在**当前包 / 当前提交**上取得可信基线，明确与 Windows 等效项的差距清单。不要求先达到某固定分钟数。

操作顺序：

1. 读最新 `memory.md`、四平台标准、本文；确认分支与工作区；源码实例与 `/Applications` 安装版不并行干扰。
2. 用当前 DMG 或经核对的源码构建，记录提交、包构建标识、helper 是否存在及哈希。
3. **播放验收（必做）**：真实账号选课节 → 预览 → 浏览器播放（单路/双路）→ 暂停拖动调速换声 → 关页返回；浅/深色、窄/宽窗、大字号各抽查。
4. **下载验收（必做）**：单路保存；双路分别保存；双路合成（高/中/低至少一档完整 + 其余短样或说明未测）。记录网络端到端与「固定本地输入的纯媒体合成」分列。
5. 按四平台 §3 核对成片：尺寸/帧数或约定时间轴、PTS/DTS、AAC 配置与顺序样本哈希（或明确「重编码例外」待用户接受）、首中尾画面、`ffmpeg -v error -xerror -i … -f null -` 退出 0。
6. **稳定性**：至少三任务入队；暂停/取消/helper 异常后后续任务仍推进；成功清理本任务临时文件且不误删成片。
7. **生命周期**：关窗（默认退出 vs 托盘）、Dock 重开、菜单退出、强制退出；退出时 helper 是否残留。
8. **文件**：保存位置可读；打开视频/定位文件夹（若尚未接入则记为缺口，不假装通过）；中文/空格路径、取消选位、不可写目标。

P0 交付：脱敏报告 + `.artifacts/macos-playback-p0/`（不入 Git 的原视频/账号）。报告模板用四平台 §8。结束条件是**可信测量与缺口表**，不是功能已完美。

### 3.2 P1：按证据定向补齐（一项一测一提交）

前置：P0 报告已列出最大缺口。按收益与正确性风险排序，每轮只做一个主题：

| 典型缺口（依 P0 调整） | 可研究方向 | 必守边界 |
| --- | --- | --- |
| F10 打开/定位 | macOS `PlaybackSavedFileActions` / NSWorkspace；与 Windows 按钮语义对齐 | 不伪造路径；旧任务无路径时明确提示 |
| F08/F13 恢复 | 任务记录、工作目录、退出取消写盘 | 先写清契约再实现；不强行声称强杀可续编 |
| F12 helper 生命周期 | 关窗/退出时停止 helper；单实例 | 不 `killall` 安装版；补桌面窗口生命周期测试 |
| F05/F06 音轨/哈希 | helper 音频路径对齐「可验收」标准 | 重编码须书面例外或改为直通 |
| 合成/下载性能 | 仅在纯媒体基准证明瓶颈后改 | 不靠降帧/丢帧；改后复测正确性 |
| 预览稳定性 | 超时、并发上限、失败重试 | 预览不整节下载、不扩域名白名单 |

每轮：固定输入/档位 → 测基线 → 修改 → 同条件复测 → 独立提交。收益不清或正确性回退则撤回该项。

### 3.3 结项条件（Mac 平台完成）

同时满足：

- F01–F14 中适用于「桌面下载+播放」的条目有证据或经明确接受的例外；
- 至少一份真实整节合成成片通过完整解码与布局抽检；
- 队列与生命周期无已知阻塞；保存可再次打开；
- 包标识与 helper 可追溯；
- 用户确认 Mac 本轮可结项（对标 Windows 用户确认流程）。

未验证边界（如特定芯片、多小时耐久）单列，不得删掉装绿。

## 4. 建议执行顺序（产品范围调整后）

1. **Windows**：已结项，不重开稳定性大项。  
2. **macOS P0**（本文）：播放 + 下载整节与差距表。  
3. **macOS P1**：按 P0 缺口补 F10/生命周期/音轨/恢复等。  
4. **Android / iOS**：只做**在线播放**验收（预览、App 内播放、错误态）；下载相关 P0/P1 与前台服务/Live Activity **不再作为产品交付**；原生下载代码可暂留，但不暴露入口、不占用结项门槛。  
5. 主干合入与发版另批，不由「Mac 平台完成」自动推出。

## 5. 本机约束（来自 AGENTS）

- `./gradlew :desktopApp:run` 最多一个源码实例；结束后按精确路径结束遗留 JVM，不用宽匹配。  
- 不关闭用户安装的「交大自由行 KMP.app」。  
- 证据进 `.artifacts/`，脱敏后才可引用进文档。  
- 验证命令在 `multiplatform/`，JDK 21；共享变更至少 `:shared:desktopTest` 与 macOS 宿主编译/启动。
