# 课程回放四平台审查标准与后续工作

更新：2026-10-31。适用分支：`feat/courseware-fallback-playback`。

本文以 Windows 已通过的课程回放验收为基准，统一各端结果、证据和收尾标准。统一的是用户能完成的事情与数据正确性，不强制使用相同播放器、后台机制或文件路径。

**产品范围（2026-10-31）**：录像**下载与合成仅 Windows / macOS**（`playbackRecordingDownloadAvailable`）；**Android / iOS 只保留在线播放**。课件文件下载不受影响。移动端原生下载/合成代码可暂留，但不作为产品入口或结项门槛。

macOS 下载+播放的分阶段任务见 [playback-macos-acceptance.md](playback-macos-acceptance.md)。Android 旧下载性能计划保留为历史参考，不再驱动移动端下载交付。

## 1. 当前结论与文档优先级

| 平台 | 当前结论 | 下一步 |
| --- | --- | --- |

| macOS | P0/P1 审查证据已齐；**真·`compose-indexed` 已落地**（边下边合等效例外已撤销）；**待用户确认结项** | 确认单 `.artifacts/macos-playback-p1/ACCEPTANCE-DECISION.md`；合主干/发版另批 |
| Android | 产品侧仅在线播放；旧整节下载证据为历史 | 验收 App 内播放/预览/错误态；下载 P0/P1 **取消作为产品交付** |
| iOS | 产品侧仅在线播放；下载/合成/后台活动实现不进入产品结项 | 验收 WKWebView 播放/预览/返回；下载整节与 AAC 合成差距 **不再阻塞产品** |

状态按以下含义使用：

- **已实现**：源码存在，不等于已运行。
- **测试通过**：写明单元/fixture/硬件/真实服务器/用户确认中的哪一类。
- **平台完成**：该平台实际支持的流程已验收，列清设备、包版本、已知限制与例外。
- **四端完成**：四端均有对应证据；Windows 的成绩不能替代其他平台。
- **发布就绪**：另需最终构建矩阵、安装/签名、版本号、主干与发布审批；不由“平台完成”自动推出。

当前状态以 `memory.md` 和本文件为准；`playback-android-performance.md` 的原分析及 `playback-composite-android-windows.md` 的旧报告只作历史与候选方案参考。若出现新实测与旧推断冲突，保留证据并更正当前结论。

Windows 完成范围包含 NVIDIA 本机真实使用与压力测试、已有 AMD 验证、保存入口和预览修复。Intel 真机、CPU 纯软件整节、多小时耐久测试未验证；Windows 中断合成后保留下载分片、继续时重新合成，是已明确的能力边界，不宣称保留编码进度。用户已要求停止网卡测速差异排查。

## 2. 四端共同功能合同

以下编号用于审查记录，不能只给一句“能下载”或“编译通过”。每项注明证据类别；不适用必须解释平台原因，不能直接留空。

| 编号 | 项目 | 通过条件 |
| --- | --- | --- |
| F01 | 入口与选课节 | 真实账号能取得课程、课节和可用画面；正常、空、过期、错误状态明确，失败不伪装成无录像 |
| F02 | 预览 | 教师/课件等可用画面有实际缩略图；短录像与第十分钟附近取帧合理；加载、失败、重试可见，离页可取消；预览不下载整节、不携带学校凭据到任意域名 |
| F03 | 在线播放 | 平台实际入口能播放/暂停、拖动、调速、切换画面/声音、双路同步、全屏进出；保持位置，返回路径清楚；默认浏览器/WKWebView/原生播放器分别取证 |
| F04 | 源与画质 | 当前源只有一档 1080p，不虚构低清下载源；单路保存为无损转封装。两路合成支持高/中/低档；实际尺寸或硬件回退必须展示，不能静默降档后当提速成绩 |
| F05 | 合成内容 | 教师左、课件右；等比缩放与黑边、方向、裁剪正确；声音来源与选择策略一致，源无音轨时如实说明 |
| F06 | 输出正确性 | 满足第 3 节的帧、时间轴、AAC、抽帧与完整解码要求；“任务完成”必须对应可打开的完整文件 |
| F07 | 队列 | 至少同时提交三项，单项运行、其余按入队顺序排队；暂停/失败/取消不堵死后续任务；重复继续不创建重复执行器 |
| F08 | 中断恢复 | 分别验证下载、合成、整理、保存中的暂停/继续和进程终止。证明哪些缓存复用、哪些工作重做；不把 UI 重建、后台返回、进程重启混为一谈 |
| F09 | 清理与数据保护 | 成功清理本任务临时文件；取消/移除按所有权清理；不删除既有成片、其他任务或无关临时文件。清理失败保留可重试记录，损坏/无法归属的记录不猜测删除 |
| F10 | 保存与重新访问 | 用户能辨认保存位置、重新打开成片并定位所在位置；处理中文/空格/重名/取消/不可写/位置失效。桌面显示完整路径与打开文件/文件夹；移动端用原生授权 URI、文件提供者或分享/导出等效实现 |
| F11 | 状态与交互 | 下载/合成/整理/保存分阶段显示；进度、有效速度、ETA 不虚假；完成/失败/暂停可辨认。浅/深色、窄/宽布局、大字号、键盘/触控可操作，错误就地说明 |
| F12 | 后台与生命周期 | 离开页面不丢任务；按平台区分关窗、托盘、后台、系统撤销时间、退出和强停；不许诺永不被杀。后台通知/活动数量和结束状态正确 |
| F13 | 持久化与账号 | 账号隔离、旧记录兼容、原子记录写入，历史加载失败不覆盖原记录；退出账号明确取消并等待停止写盘。恢复句柄不含凭据或鉴权查询参数 |
| F14 | 安装包 | 验收代码与最终包的提交/构建标识可对应；随包原生助手、配置和能力检查齐全。编译、镜像生成、安装、真机运行分别给出结果 |

F10 的平台差异不是任意豁免：在**仍提供下载**的桌面端，macOS 不应因共享界面有 Windows 按钮就勾选通过；须接 NSWorkspace 等原生打开/定位。Android / iOS 产品已关闭录像下载后，F04–F10 / F07–F09 中仅服务下载的条目对移动端标**不适用（产品范围）**，播放相关仍须验收。

## 3. 媒体正确性与性能口径

### 3.1 每次整节都必须核对

1. 记录输入指纹、两路时长/帧率/轨道、合成档位和时间轴规则；单路无损保存与双路重编码分开验收。
2. 合成输出应为选择档位的 H.264、25 fps；按显示时间检查视频 PTS 无重复/缺口，相邻间隔 40000 μs，帧数与约定时间轴一致。若有 B 帧，分别检查显示次序的 PTS、解码次序的 DTS 和 `ctts`，不能把合法重排当丢帧。
3. 同一标准样本沿用 175564 视频帧、7022.56 秒的既有基线；**其他课节另算，禁止硬编码该数或强行裁到相同帧数**。单路转封装保留源时间轴，不强制改成 25 fps。
4. 检查 AAC 配置、采样率、声道、样本数、时间戳和样本字节哈希。先剥离容器/ADTS 等封装，再用同一种方法计算顺序 AAC 样本哈希；MP4 文件哈希不同不能证明声音被改过。
5. AAC 原样复制是 Windows/Android 对照标准。源音轨已有的起止偏差要记录；比较新增的音画偏差和持续漂移，不能要求本来不同长的两条源轨强行等长。
6. 检查首/中/尾、分段连接点和恢复边界画面，核对左右、方向、黑边、裁剪及尾帧；实际播放检查音画对应。整个输出执行 `ffmpeg -v error -xerror -i <output.mp4> -f null -`，退出 0 才算完整解码通过。
7. 中断后的成片与不中断基线比较帧数、时间轴、AAC 和画面内容；不同硬件编码器的有损视频文件不要求二进制相同，但不能增加丢帧、裁剪或明显画质损失。

**已知 iOS 差距**：`AppleVideoCompositor.kt` 当前将声音读为 PCM，再编码为 48 kHz 双声道 AAC；不能通过与 Windows 同等的“原样 AAC 哈希”标准。iOS P0 必须量化该差距；后续接入 AAC 直通，或取得用户针对该差异的明确接受并写明例外，不能默认为四端一致。macOS helper 当前使用压缩音频读写，仍须实测样本哈希，不能只凭 `outputSettings=nil` 宣称通过。Apple 两端若教师路无声而改用其他路，也须记录并与界面说明一致。

### 3.2 性能比较必须拆开

| 指标 | 记录方式 |
| --- | --- |
| 纯媒体处理 | 固定本地输入，不下载、不复用已编码结果；分别记录两路解码、完整合成、整理、保存的实际边界 |
| 端到端 | 空的独立任务工作目录，从取列表/下载到成功提交目标；暂停时间另记，不能从总时长隐去 |
| 合成 FPS | 输出帧数 ÷ 合成墙钟时间；同时给出是否包含等输入、暂停、热降频或首次初始化 |
| 处理倍率 | 媒体时长 ÷ 处理墙钟时间；两路解码与只编码基准换算到同一媒体时间轴再比较，不直接比较分母不同的原始 FPS |
| 阶段耗时 | 标注下载和合成重叠；累计 `decodeMs/drawMs/encodeMs` 含等待，不等于硬件利用率，也不能直接相加当总时长 |
| 资源与环境 | 实际编解码器/GPU、供电、电量、温度、前后台、输入/输出字节、磁盘峰值与结束残留；内存/句柄/进程是否逐轮增长 |
| 网络 | 记录源字节量和下载耗时，缓存重放不计网络；网络变化不能作为编码算法提速证据。App 速度为分片处理后的平滑有效速率，不做网卡工具等值验收 |

有可重复收益且正确性、恢复和资源占用没有回退，才接受优化。9–10 分钟是 Android 目标，不是已达成绩，也不是四端必须共享的绝对时限。

## 8. 审查证据、回归和最终交付模板

所有 Gradle 命令在 `multiplatform/` 执行，使用 JDK21。共享行为变更至少运行 `:shared:desktopTest` 并编译受影响目标；Android `:androidApp:assembleDebug`；Windows `:windowsApp:windowsTest :windowsApp:compileKotlinWindows`；macOS 构建并启动；iOS 共享测试、签名模拟器/原生编译及所需真机流程。无法本地完成的目标明确交给后续 CI，未运行不写“仅 CI 已验证”。

Windows 硬件自测需本机既有 ffmpeg/ffprobe，显式启用 `BJTU_PLAYBACK_HARDWARE_ACCEPT=1` 后运行 `:windowsApp:windowsTest --tests '*WindowsPlaybackHardwareAcceptanceTest*'`。共享原生预览自测由 `BJTU_PLAYBACK_PREVIEW_ACCEPT=1` 开启，先编译 Windows helper，再运行 `:shared:desktopTest --tests '*WindowsPlaybackPreviewTest*'`。不开开关的跳过项不能当通过；ffmpeg 只作验证工具，不加入 App 运行依赖。

运行中不得重建其正在使用的共享 JAR。压力/界面测试使用固定运行副本，或先停实例再构建；构建干扰造成的类加载异常单列无效测试，不能冒充产品通过或回归。

每份平台报告至少填写：

| 字段 | 内容 |
| --- | --- |
| 版本 | 日期、分支/提交、是否带工作区修改、包构建标识、包/助手哈希 |
| 环境 | 设备/系统、GPU/实际编解码器、供电/温度/可用空间、网络及输入指纹 |
| 覆盖 | F01–F14 逐项：通过/失败/未测/经明确接受的例外；证据类别、命令、退出码、相对证据路径 |
| 媒体 | 尺寸/帧数/PTS/DTS、AAC 配置/数量/哈希、首中尾/恢复边界、实际播放与全解码 |
| 性能 | 本地媒体与网络端到端分列，阶段时间、FPS/倍率、峰值存储与异常 |
| 稳定性 | 至少三任务；Windows 同等级五轮短片压力；暂停/失败/取消/进程退出后的状态、输出及残留 |
| 限制 | 不能复现/设备不可用/未测硬件/系统后台限制；不得删除这些项使报告看起来全绿 |
| 结论 | 本平台是否可结项、需修复事项、后续兼容测试；独立于主干合入与正式发布 |

后续优先级（2026-10-31）：**Windows 已完成 → macOS P0 整节与差距 → macOS P1 定向补齐 → Android/iOS 仅播放验收**。移动端下载测量与优化不再进入该队列。
