## M15 目标

在不改变学校邮箱账号体系的前提下，使用 KMP 共享状态与 Compose Multiplatform 写一个原生邮件阅读前端。只读收件箱和邮件详情已完成首轮；写信/回复首版已接入，发送仍需真实账号风险评审。

### 信息架构

- iPhone：文件夹列表 → 邮件列表 → 邮件详情，使用平台原生二级页面；搜索和刷新保持在当前上下文附近。
- 内置文件夹按 Coremail 的实际 FID 访问：收件箱 `1`、待办邮件 `-5`、草稿箱 `2`、已发送 `3`；已删除 `4`、垃圾邮件 `5`、病毒邮件 `6` 归入“其他文件夹”。网页树节点序号不能直接当作 FID。
- iPad/macOS：窗口足够宽时显示文件夹、列表、详情三栏；中等宽度退化为列表—详情两栏；窄窗口不强行压缩列宽。
- 邮件线程、未读状态、附件和错误状态使用明确的共享模型；正文 HTML 在受控容器中显示，外链交给系统浏览器。
- 本地默认只缓存必要的列表摘要，不把完整正文、附件或 Cookie 写入普通日志/调试快照；缓存策略需在实现前单独确认。

### Apple Design 方向

- 以系统字体、动态字号、明确的标题/发件人/日期层级构成邮件行，不依赖颜色单独表达未读。
- 交互立即反馈：按下、刷新、标记已读和切换文件夹都要有即时状态；网络等待显示在当前操作附近。
- 详情页进入和返回保持同一空间路径；加载、错误和空状态使用轻量 material surface，不用无意义的弹跳。
- macOS 补齐键盘导航、悬停反馈和可调整列宽；iPhone 保持单手可达和足够的触控命中区；减少动态效果时改用淡入淡出。
