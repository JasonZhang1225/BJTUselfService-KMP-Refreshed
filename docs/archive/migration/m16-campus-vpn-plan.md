# M16 校园网 VPN 与校外访问评估

状态：**规划中，尚未登录 VPN、安装客户端或修改系统网络设置**

## 直接 MCP 取证（2026-08-28）

通过当前 Chrome 的直接 DevTools MCP 打开官方 VPN 使用说明和两个入口，得到以下可验证边界：

- `https://vpn.bjtu.edu.cn/` 可以从当前网络打开，随后显示登录页；登录页要求用户名、静态密码和动态口令。
- `https://libvpn.bjtu.edu.cn/` 同样可以打开登录页，字段相同。
- 官方说明把 `vpn.bjtu.edu.cn` 描述为“部分代理”，把 `libvpn.bjtu.edu.cn` 描述为“全代理”；页面建议使用客户端加 OTP。
- 官方页面提供 PC、Mac OS 和 iOS 相关客户端/手册入口。当前只读取了链接和说明，没有下载、安装或运行客户端。
- `https://phyvlab.bjtu.edu.cn/` 当前可直接打开公开首页，说明“物理在线”的 HTTPS 入口并不等于必须先接 VPN；公开首页可达也不能证明登录后课程、作业和提交接口在校外都可用。

## 安全边界

不采用“邪修”绕过学校访问控制的方案：不做代理转发、不抓取或转发密码/OTP、不把 Cookie/令牌放进 URL、不关闭 TLS 校验、不修改 DNS 或防火墙规则来伪造校内来源。应用也不内置校园网账号和 VPN 密码，更不代用户提交 VPN 登录表单。

VPN 属于操作系统网络设置，安装官方客户端、接受系统扩展/网络权限和建立 VPN 连接都必须由用户在自己的设备上完成；这类动作需要在具体操作前再次确认。

## M16 实施顺序

1. 用户自行选择官方说明中的 Mac 或 iOS 客户端，完成合法安装、静态密码和 OTP 登录；本项目只在用户确认后观察连接结果。
2. 在 VPN 连接前后分别测试 `phyvlab.bjtu.edu.cn` 登录页、CAS 跳转和一个只读课程/作业页面，记录 HTTP 状态、最终域名和失败原因，不记录凭据或 Cookie。
3. 对比 `vpn`（部分代理）和 `libvpn`（全代理）是否影响物理在线；若物理在线本身已经能在校外正常访问，应用不增加 VPN 依赖。
4. 若校外只能读取公开页，应用继续使用现有缓存和“同步失败·正显示缓存”语义；不以第三方代理替代学校官方网络路径。

## 验收门槛

- 明确区分“VPN 登录页可达”“VPN 已建立”“物理在线登录可用”“课程/作业只读可用”四个层次，任何一层没有证据都不宣称成功。
- 只读访问先于任何提交；物理在线真实上传仍需要单独的用户确认和可撤回/失败恢复方案。
- 最终产物保持网络状态可见、缓存可用、错误说明具体；即使用户没有 VPN，也不能因为尝试 VPN 而破坏已有的校外 HTTPS 访问。
